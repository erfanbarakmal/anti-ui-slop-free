# Component Rules

- Reuse existing components before creating new variants.
- Do not create a new button style for a single screen without a reason.
- Keep states and sizes consistent across similar controls.
- Prefer native semantic elements where possible.
- Avoid faux controls that look clickable but are static.
- Avoid clickable containers with nested competing click targets.
- Ensure icon-only buttons have names/tooltips where appropriate.
- Keep destructive actions visually and semantically clear.
- Do not turn ordinary text metadata into badges by default.
- Use badges for compact categorical or status information, not decoration.
- Use tooltips for supplemental information, never for essential instructions.
