# Layout Rules

## Goal

Create layouts that reflect the real task and content structure rather than a generic template.

## Rules

- Establish one dominant content hierarchy.
- Use containers only when they communicate grouping, affordance, or separation.
- Do not wrap every section in a rounded card.
- Reduce nesting. A card inside a card should require a strong reason.
- Use alignment and spacing before borders and shadows.
- Keep related controls near the content they affect.
- Keep global actions visually distinct from local row/item actions.
- Make data-dense interfaces efficiently scannable.
- Make reading-oriented interfaces comfortable to read.
- Do not use centered alignment as a universal default.
- Preserve consistent gutters and column rhythm.
- Use sticky behavior only when persistent access materially helps the task.

## Narrow Screens

- Reflow instead of shrinking everything.
- Collapse secondary navigation intentionally.
- Preserve primary actions.
- Avoid horizontal overflow for ordinary application UI.
- Tables may scroll horizontally only when column comparison requires it.
- Do not hide essential information merely to make mobile look clean.
