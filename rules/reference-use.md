# Reference Use Rules

1. References are for reasoning, not cloning.
2. Prefer multiple references with different purposes over one dominant visual reference.
3. The current product is always the primary source of visual language when it has an established design system.
4. Never reproduce proprietary illustrations, logos, brand assets, unique icons, marketing copy, or distinctive branded compositions.
5. Never invent a reference observation that was not actually visible or known.
6. If browsing or screenshots are unavailable, use the local reference library only as conceptual guidance.
7. When a user supplies screenshots or design files, prioritize them over generic product references.
8. Explain internally what principle is being borrowed: hierarchy, density, interaction, state handling, or responsive behavior.
9. Do not use a reference to justify unnecessary complexity.
10. The result must fit the user's product and task.
