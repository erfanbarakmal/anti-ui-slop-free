# Project Reference Router

Before substantial UI implementation, classify the project and screen.

## Step 1: Project Type
Choose the closest fit:
- SaaS / B2B
- developer tool
- AI product
- productivity / collaboration
- commerce
- content / publishing
- consumer mobile
- internal admin
- marketing site
- other

## Step 2: Screen Job
Choose the closest fit:
- dashboard
- detail page
- table / collection
- form / editor
- settings
- onboarding
- authentication
- billing
- search
- chat / messaging
- documentation
- landing page
- checkout
- empty / error / status

## Step 3: Reference Mix
Pick up to three conceptual references.
Each one must have a reason.

Good internal note:
- GitHub: table filtering and row actions
- Linear: density and navigation hierarchy
- current app: visual tokens and component language

Bad internal note:
- make it look like Linear

## Step 4: Extract Principles
Extract only relevant principles:
- hierarchy
- density
- navigation
- grouping
- states
- interaction
- responsive behavior
- accessibility

Do not extract brand identity.

## Step 5: Synthesize
Combine the selected principles with the current project's design system.
If no design system exists, define a small coherent one instead of importing the visual identity of a reference product.
